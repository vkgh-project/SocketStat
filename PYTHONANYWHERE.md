# Оновлення SocketStat на PythonAnywhere з GitHub

Інструкція для чинного сайту **https://vacula.eu.pythonanywhere.com** та репозиторію **https://github.com/vkgh-project/SocketStat**, гілка `main`.

GitHub-копія коду зберігатиметься окремо в `$HOME/SocketStat-source`. З неї в робочу папку `/home/Vacula` переноситимуться лише `socketstat/`, `requirements.txt` і `pythonanywhere_start.py`. Кореневий `.env`, папка `data/`, віртуальне середовище й налаштування сайту не копіюються з GitHub. Спосіб працює і після встановлення із ZIP: наявність `.git` у робочій папці не потрібна.

## 1. Перевірте чинний запуск

Відкрийте **Bash console** в EU-акаунті PythonAnywhere та виконайте:

```bash
pa website get --domain vacula.eu.pythonanywhere.com
```

Чинна команда запуску:

```text
/bin/bash /home/Vacula/start.sh
```

У `start.sh` виконується `cd "$(dirname "$0")"`, а потім `.venv/bin/python -m uvicorn socketstat.app:app`. Отже, робоча папка — `/home/Vacula`, Python — `/home/Vacula/.venv/bin/python`, а `/home/Vacula/socketstat` — папка Python-пакета. Скрипт оновлення не змінює `start.sh` та команду сайту.

Якщо робоча папка чи середовище інші, підставте їхні фактичні шляхи в командах нижче. Не створюйте сайт заново й не змінюйте його команду для звичайного оновлення.

Перевірте через **Files**, що чинні налаштування лежать у `/home/Vacula/.env`, а `DB_PATH` указує на наявну базу. Типове значення — `./data/socketstat.db`; відносний шлях рахується від робочої папки проєкту. Не змінюйте його під час оновлення. Якщо вебпроцес має окремо задані змінні середовища, вони мають пріоритет над `.env`: консоль для резервного копіювання повинна використовувати той самий `DB_PATH`, що й сайт.

Якщо `pa` не знайдено, установіть CLI в окремій Bash console командою `pip install --upgrade pythonanywhere`. Для його роботи потрібен API token на сторінці **Account → API token**. Команди керування ASGI й перезапуску наведені в [офіційній документації PythonAnywhere](https://help.pythonanywhere.com/pages/ASGICommandLine).

## 2. Завантажте файл оновлення

Скрипт міститься в репозиторії: [`update_pythonanywhere.sh`](update_pythonanywhere.sh).
Завантажте його в Bash console:

```bash
curl -fL https://raw.githubusercontent.com/vkgh-project/SocketStat/main/update_pythonanywhere.sh -o /home/Vacula/update_pythonanywhere.sh
```

Також можна завантажити локальний файл через **Files** у `/home/Vacula/`.

## 3. Запускайте файл для кожного оновлення

У **Bash console** виконайте:

```bash
bash "$HOME/update_pythonanywhere.sh"
```

`chmod +x` не потрібен. Скрипт сам клонує репозиторій у `$HOME/SocketStat-source`, якщо цієї папки ще немає, або оновлює наявну копію через `git pull --ff-only origin main`.

Типова робоча папка — `/home/Vacula` (логін з великої `V`), Python — `/home/Vacula/.venv/bin/python`, код — `/home/Vacula/socketstat/`. GitHub-копія зберігається в `$HOME/SocketStat-source`, резервні копії — у `$HOME/socketstat-backups`; ці папки не перезаписуються під час перенесення коду.

Якщо чинний сайт використовує іншу папку, вкажіть її під час запуску:

```bash
SOCKETSTAT_APP_DIR=/home/Vacula bash "$HOME/update_pythonanywhere.sh"
```

За потреби так само можна задати `SOCKETSTAT_SOURCE_DIR` і `SOCKETSTAT_BACKUP_DIR`. Робоча папка та GitHub-копія повинні бути окремими.

При помилці скрипт зупиниться та покаже етап, номер рядка, код завершення і шлях до резервної копії. Не запускайте reload вручну після помилки. Щоб перевірити синтаксис файлу без виконання оновлення:

```bash
bash -n "$HOME/update_pythonanywhere.sh"
```

Скрипт не копіює `.env.example` поверх `.env`, не видаляє файли та не замінює робочу БД. Перевірка `--check` перевіряє конфігурацію без запуску збирача та без запитів до Tuya. Якщо база відсутня або розміщена серед файлів коду, виконання зупиниться до перенесення коду. Файли резервної копії містять секрети: зберігайте їх приватно, не завантажуйте на GitHub.

У цьому репозиторії `.env`, `data/`, `*.db`, `*.db-wal`, `*.db-shm` також виключені через `.gitignore`. Проте наведений спосіб додатково обмежує перелік файлів, що потрапляють у робочу папку, замість покладатися лише на `.gitignore`. Якщо ви вручну змінювали Python-код, зокрема `socketstat/config.py`, ці зміни буде замінено кодом GitHub; робочі значення налаштувань мають зберігатися в `.env` або змінних середовища.

Оновлення файлів і залежностей не є атомарним: якщо помилка виникла після перенесення коду, частина оновлення вже застосована, хоча reload ще не виконувався. Збережіть шлях до резервної копії та усуньте помилку перед повторним запуском. Не запускайте другий сервер, додаткові workers або `--reload`: збирач має працювати в одному ASGI-процесі.

## 4. Перевірте результат

```bash
curl --fail --show-error https://vacula.eu.pythonanywhere.com/healthz
```

Очікувана відповідь — `{"status":"ok"}`. Відкрийте [панель SocketStat](https://vacula.eu.pythonanywhere.com), оновіть сторінку через `Ctrl+F5` або `Cmd+Shift+R`, увійдіть зі старими обліковими даними та перевірте попередню історію. Через хвилину перевірте час останнього опитування: `/healthz` не підтверджує доступність Tuya. Під час перезапуску збір короткочасно переривається.

База не підмінюється під час оновлення, але застосунок за чинною логікою видаляє спостереження старші за **14 діб**, зокрема при запуску. Це штатне очищення історії, а не перезапис БД.

## Якщо оновлення не вдалося

- Якщо `git pull --ff-only` повідомив про конфлікт або розходження гілок, зупиніться й перевірте зміни в `SocketStat-source`. Не використовуйте `git reset --hard` чи `git clean` у робочій папці.
- Якщо не пройшло встановлення залежностей або `--check`, перегляньте помилку й повторно запустіть файл після виправлення. Не замінюйте чинний `.env` шаблоном.
- Якщо сайт не піднявся після reload, отримайте шляхи до журналів через `pa website get --domain vacula.eu.pythonanywhere.com`. Попередній код лежить у `code.tar.gz`, перелік попередніх залежностей — у `requirements-before.txt` відповідної резервної копії. Відновлення коду та залежностей потребує наступного reload.
- Не відновлюйте резервну БД поверх активної: так можна втратити нові записи й пошкодити узгодженість WAL. Для відкату лише коду залишайте поточну БД; відновлення даних виконуйте окремо після зупинки всіх процесів, що її використовують.

Якщо нова версія додасть обов'язкові змінні конфігурації чи міграції БД, спочатку перегляньте її опис. Ця інструкція зберігає чинні налаштування, але не додає нові значення автоматично.
